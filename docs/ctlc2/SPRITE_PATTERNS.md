# CTLC2 스프라이트 패턴 분석

작성: 2026-09-25 · 대상: `up.exe`의 Active 오브젝트 1,545종(중복 제외), 이미지 10,936장
목적: HD 리마스터(2배 업스케일)와 Godot 이식을 위해 **스프라이트가 어떤 규칙으로 만들어졌는지** 정리한다.

> 확인 사항: 애니메이션의 프레임 번호는 **0부터 세는 값**이고 이미지 뱅크 번호는 1부터 센다(이미지 = 프레임 번호 + 1). 이 보정을 하기 전에는 애니메이션에 관계없는 그림이 섞여 보였다. 보정 후 플레이어·적·이펙트 시트가 모두 일관되게 나오는 것을 눈으로 확인했다.

## 2. 플레이어 스프라이트 (`main heros visible`)

- 애니메이션 슬롯 41개, 프레임 318개(고유 이미지 250장). 오른쪽(0)과 왼쪽(16) 방향을 **별도 이미지로** 저장했다(좌우 반전 이미지가 따로 있음).
- 캔버스 약 50~65 × 92~107px. 원본 화면 높이(480)의 약 21%.
- **핫스팟 = 발 밑 가운데** (예: 63×103 프레임의 핫스팟 (32,102)). 지형 충돌 기준점이다.

## 3. 적·보스 스프라이트

- 일반 적은 애니메이션 **1~6개**: 대기, 이동, 공격 1~2종이 기본이다. 예: Hunter Skeleton = 대기 1 · 걷기 6 · 공격 5 · 공격 5.
- 사망 연출은 애니메이션이 아니라 **별도 오브젝트**(`debris`, `restes`, `os`)로 만든다. 잔해 조각을 흩뿌리는 방식이다.
- 투사체도 별도 오브젝트(`tir`, `shot`).
- 보스는 몸통 하나에 애니메이션을 몰지 않고 **부위별 오브젝트**로 나눈다(예: Leviathan 본체 + 팔 + 입 + 공격 오브젝트, Death Plant는 몸통 마디 `seg1~seg6`).
- 속도 중앙값 30, 적은 색(6~27색)의 픽셀아트가 많다.

## 4. 이펙트 스프라이트 (`A.main impact/fumées/explo`)

- **이펙트 은행**: 오브젝트 하나에 이펙트 23종을 슬롯별로 담았다(타격 불꽃, 연기, 폭발, 파편 등). 대부분 4~9프레임, 속도 25~80, 크기 12~60px.
- 방향 슬롯을 **회전 사전 렌더**로 쓴다: `0,4,8,…,28` = 8방향 회전 이미지를 미리 그려 둠.
- 방향 슬롯을 **변형 번호**로도 쓴다: `0,1,2,3,4,5` = 같은 이펙트의 크기·색 변형 6가지.

## 5. 제작 관습 요약

1. **좌우를 별도 이미지로** 저장 → 이미지 수가 거의 두 배.
2. **핫스팟 = 발 밑**, **액션 포인트 = 무기·손·발사 위치**. 판정과 이펙트 위치를 이 두 점으로 맞춘다.
3. **상태이상 = 색을 바꾼 프레임을 따로 그림.**
4. **사망·투사체 = 별도 오브젝트.**
5. **방향 슬롯을 방향이 아닌 용도(변형·회전)로 재활용.**
6. **투명색 = 검정.** 가장자리에 반투명 픽셀이 없다(1비트 투명).
7. 무기가 바뀌면 공격 애니메이션을 통째로 한 벌 더 그림(23/52, 24/53).

## 6. Godot 이식 규칙

| CTLC2 관습 | Godot 방식 | 효과 |
|---|---|---|
| 좌우 별도 이미지 | 한쪽만 가져오고 `flip_h` | 이미지·업스케일 작업량 절반 |
| 핫스팟(발 밑) | `AnimatedSprite2D.offset`을 발 밑 기준으로 맞추고 CharacterBody2D 원점 = 발 | 충돌 기준 일치 |
| 액션 포인트(프레임별) | `AnimationPlayer` 트랙으로 `Marker2D` 위치와 `Hitbox` 켜기/끄기를 프레임마다 키 | 판정·발사 위치가 데이터로 남음 |
| 색조 프레임(상태이상) | 셰이더 파라미터(`tint`, `flash`)로 처리 | 프레임 3세트 삭제 |
| 무기별 공격 애니메이션 복제 | 몸 동작 1벌 + 무기 스프라이트를 손 `Marker2D`에 붙임 | 무기 추가 시 몸 애니메이션 재작업 없음 |
| 방향 슬롯 = 변형 | `SpriteFrames`의 이름 있는 애니메이션으로 분리(`hit_small`, `hit_large`) | 의미가 보임 |
| 8방향 회전 사전 렌더 | 1장 + `rotation` | 이미지 1/8 |
| 이펙트 은행 | 이펙트마다 작은 씬(`fx/hit_spark.tscn`) 또는 `GPUParticles2D` | 재사용·조명 적용 |
| 사망 잔해 오브젝트 | `GPUParticles2D` 또는 RigidBody2D 파편 씬 | 물리 반응 |
| 검정 투명색 | 가져오기 전에 **검정 → 알파 0** 변환 | 업스케일 시 검은 테두리 번짐 방지 |
| 속도 값(0~100) | 60fps 기준 대략 `fps ≈ 속도 × 0.6`로 환산 후 눈으로 조정 | 초기값 확보 |

## 7. HD 리마스터에 주는 영향

- **해상도 기준 정정**: 원본은 640×480 화면에 키 약 100px 캐릭터(화면 높이의 21%)다. 에셋을 2배로 키우면 약 200px이 된다. 이 비율을 유지하려면 **1920×1080에서 네이티브로 그리고, 화면에 보이는 월드는 원본 픽셀 기준 960×540**이어야 한다(키 200px ÷ 1080 = 19%). 설계서의 "960×540 내부 렌더 후 2배 출력"은 2배 에셋과 맞지 않아 이 방식으로 고친다.
- 4:3 → 16:9로 바뀌므로 한 화면에 보이는 가로 폭이 1.5배가 된다. 방 설계와 카메라 경계를 다시 잡아야 한다.
- 업스케일 순서: 검정 → 알파 변환 → 2배 업스케일 → 윤곽 손보정 → 노멀맵 → Godot 가져오기.
- 플레이어는 색이 많은 음영 그림(207색)이라 AI 업스케일이 잘 맞고, 적은 색이 적은 픽셀아트(6~27색)라 픽셀아트 전용 스케일러(xBRZ 계열)가 맞다. **종류별로 스케일러를 나눠 쓴다.**
- 좌우 중복을 빼면 플레이어 업스케일 대상은 318프레임에서 약 150프레임으로 줄고, 상태이상 색조 프레임을 셰이더로 돌리면 더 준다.
