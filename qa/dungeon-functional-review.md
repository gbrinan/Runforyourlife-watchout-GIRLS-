# 지하실 던전 독립 기능 검토

검토일: 2026-09-07. 범위: 사용자 추가 요청인 천장 닫힌 지하실 분위기 전환과 기존 M1 행동의 연결. M1.5 문 파괴·출구 서사는 인수 범위에서 제외한다.

판정: 소스 및 실제 캡처 기준 기능 승인. 발견한 벽 너머 들이받기 결함은 수정되었다. 최종 전체 자동 검사 결과는 plan/progress.md 정본을 따른다.

## 증거와 확인

- src/render/dungeon.ts의 64×64 평면 천장은 y=3에서 아래쪽을 향한다. 높이 3m의 인스턴스 벽은 충돌에 사용하는 같은 layout.cells의 경계를 따른다. 천장·벽은 실제 메시이며 배경 그림이 아니다.
- qa/dungeon-start-1280.jpg, dungeon-play-1280.jpg, dungeon-death-1280.jpg를 직접 열어 연속된 천장, 보, 석조 복도, 조명, 적과 사망 화면을 확인했다. 375/768 시작 화면도 직접 검토했고 주 내용과 버튼이 화면 안에 들어온다.
- gen/dungeon.ts의 방 5개가 폭 3칸 복도로 연결된다. BFS 경유점은 중간 목표와 최종 목표를 분리하며, 코너 시야가 막히면 현재 셀 중심으로 먼저 이동한다. maiden.ts는 중간 경유점 도착만으로 탐색 상태로 바꾸지 않는다.
- 플레이어 이동은 벽 충돌 시 축별 미끄러짐을 시도한다. 최대 프레임 이동은 0.4m로 1m 벽보다 작다. 적은 최대 0.225m 이동 후 막힌 위치를 되돌린다. 시야 판정에는 벽 검사가 포함된다.
- 첫 검토에서 F가 벽 건너 적을 밀거나 세 번째 타격으로 플레이어를 해치는 결함을 발견했다. 현재 src/main.ts는 ramInDungeon을 호출하며, 이 함수는 변이 이전 시야 검사와 0.2m 간격의 밀기 경로 충돌을 적용한다. 회귀 테스트는 벽 너머 첫/세 번째 타격의 무변이, 합법적 밀기의 벽 정지와 세 번째 잡힘을 구분한다.
- 기존 소음·추격·수색·스태미너·피해·재시작 흐름은 환경 교체와 연결되어 있다. 오디오 버스는 직접음과 두 개의 저역 통과 지연 경로를 구성한다.

## 검증 한계와 반대 관점

이 검토자는 소스와 제공된 실제 화면을 검토했다. 직접 게임 입력 재현이나 청취를 수행한 것으로 주장하지 않는다. 독립 테스트 실행은 PowerShell PATH에 npm이 없어 시작되지 않았으며 테스트 실패를 뜻하지 않는다. 구현자의 최종 검사 및 브라우저 조작 기록은 plan/progress.md에서 확인한다.

따뜻한 조명과 천장은 요청한 분위기를 충족하지만, 복잡한 던전 탐험·승리 목표까지 완성되었다고 볼 수는 없다. 오디오 잔향은 전역 지연으로 벽별 음향 시뮬레이션이 아니며, 공포감·HRTF·실기기 60fps는 사람과 실제 장비 평가가 남는다. 이는 명시된 환경 전환 범위의 차단 사유는 아니다.

## 최종 자동 검사 인계

구현자가 최종 코드에서 실행한 결과를 전달받았다: tsc --noEmit 통과, vitest run --coverage 11파일 92/92 통과, 구문 97.32%·분기 91.96%, dungeon-combat 구문 100%, dungeon 구문 100%·분기 98.14%, Vite 빌드 전체 gzip 134.46KB. 실제 추격의 connected/corner/continuous3 코너 회귀도 통과했다. 실행 명령과 정본 증거는 plan/progress.md를 따른다.

최종 프로덕션 캡처 qa/dungeon-final-play-1280.jpg도 직접 열어 천장·석조 복도·근접한 적과 피해 자막이 렌더링됨을 확인했다. 구현자의 최종 브라우저 점검은 Enter 시작, Escape 정지 및 콘솔 오류/경고 없음으로 전달받았다. 최종 판정: 승인, 열린 기능 차단 결함 없음.
