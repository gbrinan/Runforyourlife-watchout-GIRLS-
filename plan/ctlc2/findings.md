## 발견
- 2026-09-25: 엔진은 **Clickteam Fusion 2.5 빌드 287**. 원본 프로젝트 파일명 `Lecarde chronicles II catoblepas 3.mfa`가 exe에 남아 있다.
- 2026-09-25: exe 구조 = PE(약 390 KB) + overlay. overlay = 런타임 팩(30파일: stdrt.exe, mmfs2.dll, DX9/DX8 렌더러, 확장 .mfx/.mvx, 오디오 필터) + `PAMU` 게임 데이터.
- 2026-09-25: 규모 — 프레임 47, 오브젝트 4,812, 이미지 10,936, 사운드 668(풀면 약 150 MB), 이벤트 129,813줄(조건 293,854 · 액션 398,851).
- 2026-09-25: **코어 이벤트 블록(그룹 27개, 스테이지당 약 2,560줄)이 47개 프레임 전부에 있고, 스테이지 28곳에서는 그룹별 이벤트 수가 한 자리도 다르지 않다.** 공유 엔진이 없고 프레임마다 복제된 구조.
- 2026-09-25: **INI 확장(kcini) 호출 17,027회**. 세이브뿐 아니라 프레임 간 상태 전달도 INI 파일 I/O로 한다. `READ ME.txt`의 "MAP/SUBSCREEN 진입 시 크래시 = 데이터 쓰기 실패" 증상과 일치.
- 2026-09-25: LOADING 프레임의 세이브 슬롯 1/2/3 로직이 각 70줄로 동일하게 복제. INI 키는 `100`~`123` 같은 숫자.
- 2026-09-25: SUBSCREEN의 장비 카테고리(검·갑옷·투구·반지·목걸이)가 각각 정확히 100줄 → 슬롯 하드코딩. 몬스터 도감 642줄, 아이템 획득/판매 409줄.
- 2026-09-25: 적 1종 = 이벤트 그룹 1개(44~130줄). 공통 AI 부품 없음. 오브젝트는 `E-<이름>` 본체 + `tir/debris/restes/os/mortem` 변형.
- 2026-09-25: 명명 접두어 규칙 `A.`(시스템) / `E-`(적) / `S.`(장치) / `B.`·`B.D.`·`C.`(배경).
- 2026-09-25: 입력(`CONTROL CENTRAL SYSTEM` → `A.main true controller`)과 사운드(`A.main SOUND calculator`)는 중앙화되어 있어 좋은 패턴.
- 2026-09-25: 스테이지 레이어 7장, 스크롤 계수 0 / 0.2 / 0.5 / 0.75 / 1 / 1 / 1 (패럴랙스 규약).
- 2026-09-25: 텍스트는 언어별 오브젝트 7개(ENG/FR/ES/GER/ITA/JAP/BRA)로 병렬 관리.

## 기술 결정
- 분석 도구는 Python 표준 라이브러리만 사용(zlib, struct, mmap). 외부 추출기 다운로드 없음.
- 복호화: Fusion 2.5 빌드 >284 방식. 키 문자열 = 앱 이름 + 프로젝트(.mfa) 경로, magic 54, RC4 계열. 청크 id가 홀수면 첫 바이트 추가 XOR.
- 이벤트 파싱: `ER>>` 헤더 → `ERes` → `ERev` **여러 블록** → `<<ER`. 이벤트 = `[i16 -size][u8 조건수][u8 액션수][flags...]`, 그룹 시작/끝 = 시스템 조건 (-1,-10)/(-1,-11).

## 이슈와 해결
- 조건/액션 번호의 이름 매핑이 없어 그룹의 역할은 그룹 이름(프랑스어 주석)·참조 오브젝트·문자열 파라미터로 추정했다. 정확도를 높이려면 매핑 표가 필요(tasks Q3).
- 2개 exe(`up`, `upc`)의 차이는 미분석. README상 `upc`는 대체 영상 모드(AVM)판으로 보인다.
